# ADR-0024: Frontend shared components — amounts, dates, page states and a component catalog

- **Status**: Accepted
- **Date**: 2026-11-17
- **Deciders**: Paul

## Context

- Amounts are JSON numbers with at most 2 decimals; the API refuses a third decimal and never rounds, and the client never adds amounts up ([ADR-0015](0015-resource-conventions-and-accounts.md), [ADR-0010](0010-data-model-and-user-isolation.md)). People type them the Italian way (`1.234,56`), often on a phone whose decimal keyboard may offer only a dot.
- Transaction dates are calendar dates (`DateOnly`, `YYYY-MM-DD`) and months are `yyyy-MM`; the Definition of Done asks that a date never moves by a day because of a time zone. Material's native date adapter works on `Date` objects at local midnight.
- Safari does not support `Temporal` yet (Chrome 144 and Firefox 139 do), and the app is meant for phones, iPhones included.
- Angular 22 Signal Forms offer `FormValueControl` and `transformedValue` for custom controls with parse errors.
- The roadmap adds a PWA with an offline queue, CSV import and export, multi-currency accounts and other languages.
- The dark-mode income color (tone 80 of Material's `$green-palette`, `#02e600`) looked neon next to the rest of the theme (block 1 review).
- The plan of block 4 also listed a filter bar and account/category selectors; their only consumers arrive in blocks 5 and 6, together with the reference data they need.

## Decision

1. **Scope**: block 4 builds what has a consumer soon and needs no feature data: amount input and display, ISO dates and the date picker adapter, a month selector, empty / error / loading states, the income color. Account and category selectors move to block 5 (with the reference data in `core`), the list filter bar to block 6 (with the movement list).
2. **Amounts as `number`** (`shared/money`): `parseAmount()` reads Italian text through the string (`12,5`, `1.234,56`, `12.5` from a dot keyboard; `1.234` is a thousand), refuses a third decimal, negatives unless allowed, and more than 12 integer digits (where cents stop being exact); `formatAmountInput()` and `formatAmount()` / `AmountPipe` write it with `Intl` in the app locale. `<app-amount-input>` is a Signal Forms `FormValueControl<number | null>` that contains its Material form field (label, currency suffix, hint, first error once touched) and reports unreadable text as a parse error with `transformedValue`, so the form cannot be submitted. Use-specific rules (required, greater than zero) stay validators of the form.
3. **Dates as `YYYY-MM-DD` strings** (`shared/dates`): an own `IsoDateAdapter extends DateAdapter<string>` provided once in `app.config`; computations work on the numbers (`Date.UTC` only for the calendar), formats run in UTC, typed dates are read day first (`17/11/2026`, `17/11/26`); `todayIso()` is the date on the person's clock. Helpers for months (`currentMonth`, `addMonthsToMonth`, `monthRange`, `formatMonth`). The fields live in `shared/date-pickers`, never in the barrel imported at startup: `<app-date-input>` (a Signal Forms control like the amount input: Italian parse message, Italian calendar texts, calendar in a dialog on phones) and `<app-month-selector [(month)]>` for budgets and the dashboard. Tests run in `Pacific/Kiritimati`, `America/Los_Angeles` and `Europe/Rome`, the date picker included.
4. **Page states as small components**: `<app-empty-state>` (`shared/ui`: icon, title, message, projected action) and `<app-error-state>` (`core/feedback`, since it reads `ApiError`: Italian message, "Riprova", copyable reference); loading is Material's progress bar. Pages choose with `@if` on the resource status.
5. **Income green from a generated palette**: `_income-palette.scss` generated by Material's `theme-color` schematic from `#2E7D32`; `--pf-income` keeps tones 40 / 80 (`#1b6d24` / `#88d982`), with the same contrast as the error role it sits next to.
6. **Component catalog in development only**: `/dev/components` shows every shared component with live values. The production build replaces `dev-routes.ts` with an empty list (`fileReplacements`), so no byte of it reaches the production bundles. The initial bundle budget now fails the build above 600 kB (warning at 500 kB): during the review a component exported from the startup barrel silently raised it from 481 kB to 779 kB.

## Consequences

**Positive**
- Forms hold exactly what the API takes: no conversion in services, in the PWA queue or in CSV import, which can reuse `parseAmount()` and the date helpers per row.
- No `Date` in date fields, so no day shift whatever the time zone of the phone; switching to `Temporal.PlainDate` later only changes the adapter.
- Another language or currency is the locale and the `currency` input: formatting is `Intl`, not hand-written.
- Every component is tried in a real browser, on phone and desktop, before a page uses it.
- Blocks 5 and 6 build selectors and filters with their real data instead of guesses.

**Negative**
- An own parser and date adapter to maintain, with their tests.
- The amount input sets its own label and errors instead of being dropped into any `mat-form-field`.
- The generated palette file stays in the repository.
- The dev page needs `ng serve` and a session to be seen.

## Alternatives considered

**Amounts as decimal strings or integer cents** — Rejected: exact, but every service, the offline queue and the import would convert them to the API's numbers, for arithmetic the app never does.

**`<input type="number">`** — Rejected: no Italian comma on many keyboards, scientific notation, silent rounding, different behavior across browsers.

**Material's `NativeDateAdapter` with conversions at the edges** — Rejected: forms would hold `Date` at local midnight, and one `toISOString()` moves the day.

**`Temporal.PlainDate` adapter** — Rejected for now: Safari lacks `Temporal` and a polyfill is heavy for a phone app. Reconsidered when Safari ships it.

**One `<app-resource-view>` wrapper for every state** — Rejected: less explicit, and harder to adapt (a list loading its next page under the current one).

**Another tone of Material's green palette, or the theme's tertiary role** — Rejected: every tone is very saturated; the azure theme's tertiary is not green.

**Trying the components in placeholder pages, or not at all** — Rejected: placeholder forms would be rewritten in block 6; without a browser check, layout problems (like the ones found in blocks 1–3) would surface only with the real pages.
